# ตรวจสอบการเปลี่ยนเป็น AI Learning Studio

## สิ่งที่เปลี่ยน

- Sidebar เลือก AI ตามลำดับ Nui, Saimai, Bam, Bas, Kaka, SabaiTae
- ทั้งหกใช้ฐานความรู้และขอบเขตบทเรียนเดียวกัน เปลี่ยนเฉพาะรูปแบบการสอน
- ใช้ชื่อผู้เรียนเพื่อแสดงผล ไม่ใช้ชื่อเป็นตัวค้นประวัติ
- ประวัติแยกตามรหัสสุ่มของเบราว์เซอร์และ AI ที่เลือก
- ฐานข้อมูลเก็บ hash ของรหัส ไม่เก็บรหัสเบราว์เซอร์โดยตรง
- ตารางใหม่ไม่แทนที่หรือลบประวัติแบบเดิม
- ใช้โทนสีและโครงหน้าจาก Stitch โดยไม่เพิ่มปุ่มจำลองที่ใช้งานไม่ได้

## การจำประวัติ

รหัสเบราว์เซอร์เป็นกุญแจเข้าถึงประวัติ ไม่ใช่ระบบล็อกอิน
ชื่อเหมือนกันไม่รวมประวัติ และเปลี่ยนชื่อไม่เปลี่ยนเจ้าของประวัติ
ล้างข้อมูลเว็บไซต์ เปลี่ยนเบราว์เซอร์ หรือเปลี่ยนเครื่อง จะไม่เห็นประวัติเดิม
หากเบราว์เซอร์ปิดกั้น storage ระบบจะแจ้งว่าจำได้เฉพาะ session
ควรหลีกเลี่ยงใช้บนเครื่องสาธารณะ

ตาราง `browser_chat_owners` และ `browser_chat_exchanges` อยู่ใน
[chat_history.sql](../db/chat_history.sql) และเปิด Row Level Security
โดยไม่สร้าง public API policy ใช้ผ่าน PostgreSQL ฝั่ง server เท่านั้น
การบังคับ RLS ต้องตรวจด้วย PostgreSQL จริง ไม่ใช่ SQLite

## สถานะการตรวจ

ตรวจเมื่อ 29 กันยายน 2026:

- `venv/bin/python -m unittest discover -s tests`: ผ่าน 115 รายการหลังแก้รอบสุดท้าย
- ชุดเฉพาะ UI/history/identity/avatar/exception AppTest: ผ่าน 22 รายการ
- `node tests/test_browser_identity.mjs`: ผ่าน การจำรหัส รหัส canonical
  การอ่านกลับหลังเขียน storage กรณี storage ถูกปิด และ race จำลอง
- Chrome จริง: ตรวจ DOM และภาพ desktop กับมือถือ 390×844
  ตรวจการสลับ AI และปุ่มภาษา ช่องถามไม่ถูก sidebar บัง
  ปุ่มภาษาอยู่ขวาของช่องถามใน desktop และเหนือช่องถามในมือถือ
- PostgreSQL จริง: schema, เจ้าของ/AI แยกกัน, ชื่อซ้ำ, เปลี่ยนชื่อ,
  preview bytes, retry ไม่ซ้ำ, ลบเฉพาะ AI และ RLS ของ role authenticated ผ่าน
  ตรวจใน transaction ที่ rollback ทั้งหมด ไม่ทิ้งข้อมูล/schema ทดสอบ
- RAG + Gemini จริง: Nui ตอบ Bubble Sort ภาษาไทย และ Saimai ตอบ
  Counting Sort ภาษาอังกฤษ ได้หลักฐาน 5 chunks ต่อคำถาม
  ไม่มีการ re-index หรือบันทึกบทสนทนาจากสคริปต์ตรวจนี้
- Chrome + แอปจริง: สร้างโปรไฟล์ `UI QA` และถาม Bubble Sort หนึ่งครั้ง
  แสดงสถานะบันทึกสำเร็จ รีเฟรชแล้วยังเห็นคำถาม/คำตอบและแหล่งอ้างอิง
  เปิดแท็บใหม่ได้ชื่อเดิมและคำถามเพียง 1 ชุด สลับ Bas ไม่พบข้อความของ Nui
  เปิดภาพหลังโหลดประวัติแล้วได้ภาพ Bubble Sort ทั้งสามภาพ
  แอปสร้างตารางประวัติใหม่จริงในขั้นนี้ ไม่ลบ/ย้ายตารางหรือประวัติเดิม
  มีโปรไฟล์และบทสนทนา QA ใหม่นี้คงไว้ ไม่มีการยืนยันลบทดสอบผ่าน UI
- `git diff --check`: ผ่าน
- Python compileall ของ app/rag/ui/tests: ผ่าน

มีคำเตือนจาก parser PDF เรื่อง fontTools/offset ในเอกสารเดิม,
คำเตือน bare-mode ของ Streamlit AppTest และคำแนะนำ AFC ของ google-genai
ชุดเทสผ่าน แต่ไม่ได้หมายความว่าไม่มี warning หรือรับประกันไม่มีบั๊ก

ยังไม่ได้ตรวจ:

- ปิด Chrome ทั้งโปรแกรมแล้วเปิดใหม่ (ตรวจเปิดแท็บใหม่และรีเฟรชแล้ว)
- เปิดหลายแท็บจริงพร้อมกันเพื่อทดสอบการแย่งเขียนรหัสเบราว์เซอร์
- ทุกบุคลิกกับทุกคำถาม/อุปกรณ์ ไม่ใช่เพียงกรณีที่ตรวจครั้งนี้

ช่วงตรวจหน้าจอแรก port 8502 ปิด API key และฐานข้อมูลโดยเจตนา
ต่อมาเปิดแอปจริงที่ port เดิมด้วย `.env` ฝั่ง server เพื่อทดสอบประวัติครบวงจร
ไม่ได้เปิดเผย API key/URL/รหัสผ่าน/รหัสเจ้าของจาก browser storage
ไม่ได้หยุดแอปของผู้ใช้ที่ port 8501

## การตรวจเพิ่มเติมจาก review และผู้ใช้

- Review แยกบน checkpoint `5a46415` พบกรณีเจ้าของเปลี่ยนขณะ DB ล่ม,
  การกู้ประวัติทับคำตอบ session, ลบเฉพาะหน้าเว็บทั้งที่ DB ยังมีข้อมูล,
  และรายละเอียด exception หลุดออกหน้าจอ แก้ในรอบถัดมาพร้อม regression
- ตรวจข้อมูล component: `persisted` ต้องเป็น boolean จริง ไม่ยอมรับ string
  ที่ดูเหมือน false แต่ถูก Python มองเป็น truthy
- ตั้งชื่อยังพยายามบันทึกเมื่อโหลดประวัติมีปัญหา และแสดงคำเตือนหากไม่ได้บันทึก
- ใช้ Web Locks จัดลำดับการสร้างเจ้าของในหลายแท็บเมื่อ browser รองรับ
  มีเทสการรอ lock และสองแท็บใช้รหัสเดียวกัน; fallback ที่ไม่มี Web Locks
  ไม่อ้างว่าป้องกันทุก race ได้
- บั๊กปุ่มภาษาหายเมื่อเลื่อนล่างสุด: Chrome ซ่อน element ที่อิง anchor
  เมื่อหัวแชทพ้นจอ แก้ด้วย `position-visibility: always`
  ตรวจ Chrome จริงโดยเลื่อน Control+End และกด English สำเร็จ
- รอบแก้หลัง review เป็นการแก้และตรวจโดย main ไม่ใช่คำรับรองว่า reviewers
  ทดสอบโค้ดหลังแก้ซ้ำทั้งหมด

## เพิ่มเอกสาร Merge Sort

ตรวจ `real_data/Merge_Sort_Complete_Book_TH.pdf` ครบทั้ง 31 หน้าและตรวจภาพ
crop สำหรับผู้เรียนครบ 16 ภาพที่ขนาด 2× ก่อน ingest

- Manifest ผูกเอกสารกับ SHA-256 และระบุ scope ของทุกหน้า
- เพิ่ม 32 chunks ครอบคลุม 31 หน้า; 22 primary และ 10 reference-only
- โค้ด Python, pseudocode, recursion trace, dry run, stability,
  bottom-up, complexity/space และ debugging table มี crop/label แยกตามหน้าที่
- หน้า External Merge Sort, หน้าสรุป/ตารางผสมหัวข้อนอกบท,
  ตารางที่ glyph เสีย และหน้าบรรณานุกรม ไม่ถูกเลือกเป็นภาพผู้เรียน
- สำหรับไฟล์นี้ใช้ PyMuPDF เพื่อรักษารูปแบบโค้ดและลดปัญหาวรรณยุกต์ไทยซ้ำ
- เพิ่ม index เฉพาะเอกสารนี้ลง PostgreSQL + pgvector; ตรวจพบ chunks 32/32
  มี embedding และภาพที่ระบุ user-visible 16 ภาพ
- เพิ่มคำกันเขตสำหรับหัวข้อนอกหลักสูตรที่เอกสารกล่าวถึง เช่น External,
  Cocktail, Shell และ Batcher และจัดอันดับ code query ให้ implementation
  มาก่อนย่อหน้าภาพรวม
- ตั้ง Nui, Saimai และ Bam ใช้สรรพนามและคำลงท้ายแบบผู้หญิงใน welcome,
  คำตอบระบบสำเร็จรูป และคำสั่ง persona สำหรับคำตอบจากโมเดล
- ตรวจ PostgreSQL หลัง ingest: 13 documents, 204 physical pages,
  243/243 chunks มี vectors, 256 visuals รวม; selector คืนเฉพาะ 16 reviewed crops
- ตรวจ Gemini + PostgreSQL จริง: คำถามโค้ดขึ้นหน้า 14 เป็น hit แรกและคืน
  implementation ที่รันได้; คำถาม dry run มี trace และภาพหน้า 10
- ตรวจ scope จริง: External Merge Sort, Cocktail Sort, Shell Sort และ
  Batcher Odd-Even Merge ได้คำตอบชี้แจงว่าอยู่นอกหัวข้อหลัก

ผลตรวจรอบเตรียม push:

- `venv/bin/python -m unittest discover -s tests -p 'test_*.py'`: ผ่าน 122 tests
- `compileall`, `git diff --check` และตรวจ JSON ของ manifest: ผ่าน
- แอปที่ port 8502 และ Streamlit health endpoint ตอบ HTTP 200
- รอบนี้ Browser runtime แจ้งว่าไม่มี browser ให้เชื่อม จึงไม่ได้ตรวจ DOM/ภาพ
  ซ้ำหลังรีสตาร์ต; การตรวจ Chrome ก่อนหน้านี้เป็นผลจากรอบก่อน ไม่ใช่รอบนี้

ผลนี้ยืนยันชุดทดสอบและ health endpoint เท่านั้น ไม่ใช่การรับประกันว่าไม่มีบั๊ก

## การทดสอบก่อนใช้งานจริง

1. ตั้งค่า secrets ฝั่ง server โดยไม่ใส่ลง Git
2. เปิดแอปจริงและตรวจว่าตารางประวัติสร้างสำเร็จ
3. ใช้ชื่อเดียวกันในสอง browser profiles แล้วถามคนละคำถาม
   ประวัติต้องไม่ปะปน
4. สลับ AI ทั้งหก ถาม แล้วรีเฟรช ประวัติต้องกลับมาที่ AI คนเดิม
5. เปลี่ยนชื่อ ประวัติต้องยังอยู่
6. ตัดการเชื่อมต่อฐานข้อมูล ระบบต้องแจ้งบันทึกไม่สำเร็จ
   และไม่ลบข้อความที่แสดงไปแล้ว
7. ทดสอบยกเลิกและยืนยันลบแชท ต้องกระทบเฉพาะ AI ที่เลือก
8. ทดสอบภาษาไทย/อังกฤษ การอ้างอิงและภาพต้องตรงกับคำถาม
9. ตรวจ desktop/mobile ว่าช่องถามและปุ่มภาษาไม่ทับกัน
